# Brood Benchmarks — the data

The numbers, in one place. Full machine-readable tables (wall time, peak RSS, checksums,
per-language ranks): [`results/report.md`](results/report.md) /
[`results/results.json`](results/results.json), regenerated by the harness on every run. The
analysis of *why* Brood lands where it does and what would move it: [`FRONTIER.md`](FRONTIER.md).

Machine: `whklat`, 12-core x86-64, Linux 7.0.0, **2026-07-27** · Brood 0.1.0 (`1a3fc1c`) · Clojure 1.12.5 /
JDK 25.0.3 · Elixir 1.21.0-dev / OTP 28 · Python 3.14.4 · Node 22.21.0 · Ruby 3.3.8 · .NET 10.0.110.
Best of 3 runs (the concurrency rows best of 7); each run `taskset`-pinned (compute → 4 dedicated
cores, concurrency → all 12) with a 0.25 s settle, after one discarded warmup run per language.
Every program prints one integer and the harness asserts all seven agree, so the work is provably
equivalent. Methodology and fairness notes: [README](README.md).

**<sup>c</sup> Clojure runs cold.** The JVM cold-starts (~0.33 s) on every single-shot run and
HotSpot never fully JIT-compiles the hot loops in that window — a long-running Clojure service
would be far faster than every number in its column.

**<sup>p</sup> Precompiled.** Elixir and .NET are built once and run as compiled artifacts, so
per-run compilation never leaks into their compute. Brood, Clojure, Python, Node and Ruby run from
source each run. This favours Elixir and .NET, and is the fair analog of `node app.js`.

**<sup>a</sup> Algorithmic asymmetry, against Brood.** `primes`: most languages hoist a `sqrt` bound
where Brood/Clojure re-test `(* d d) > m` each step. `strings`: Brood/Elixir join the range
directly.

**<sup>d</sup> Different data structures, by language.** `wordcount`/`persistent-map` pit
**immutable** persistent maps (Brood/Elixir/Clojure) against **mutable** dicts and hashes
(Python/Node/Ruby/.NET). `sieve` and `nbody` are worse for Brood specifically: it has no mutable
array, so it marks composites in a `Table` and rebuilds immutable body vectors every step where
the others mutate one buffer in place.

**<sup>l</sup> Pure-Brood library vs native.** `json`/`regex`/`base64` run Brood's in-language
`std/` codecs against C/JVM ones. Deliberate — the row measures the *library*, not the VM.

**<sup>n</sup> Denominator at the noise floor.** These sizes are small precisely because Brood is
slow there, so the fast runtimes finish in single-digit ms and the ordering *among them* is
meaningless. Read Brood's absolute number, not the ratio.

**<sup>g</sup> Slower than the 2026-07-26 run, deliberately.** `fib` 57 → 75 ms and `pfib`
165 → 218 ms (~+30% each; `pfib` is 100 concurrent `fib`s, so it is the same cost seen twice).
Bisected to brood `f11f4cb`, which closed a crash: deep recursion through JIT'd code could run the
*native* stack into its guard page, an abort that takes the whole OS process and that `try`/`catch`
can never see. The fix stamps a stack limit before entering native code and checks it in every
lowered arm's prologue, and makes the dispatch-path headroom probe unconditional — so `fib`, which
is nothing but calls, pays it per call. A three-binary A/B (`26939e2` / `f11f4cb` / `1a3fc1c`,
best-of-7 each) puts the entire move on that one commit and nothing after it. A crash became a
catchable error; the cost is recoverable (see [`FRONTIER.md`](FRONTIER.md)) and has not been
recovered yet. Both ranks are unchanged.

**<sup>i</sup> Idiomatic concurrency, not identical machinery.** Each language uses its own
primitive — green processes for Brood/Elixir, Promises/`worker_threads` for Node, asyncio or
thread pools for Python/Ruby, `future`/`pmap` for Clojure, tasks and channels for .NET. So these
rows compare *how you would actually write this*, which is the intent. Node's `ring` win in
particular is cooperative single-thread async, not isolated processes.

The first 15 rows and `spawn`/`pfib`/`http` are the original core suite; the rest widen coverage
past the numeric/allocation core (recursion depth, mutable-array algorithms, immutable-structure
churn, float physics, text/parsing, message latency). **No row is last-of-seven.** Run-to-run the
field drifts ±10%, so read the ordering rather than the digits.

**Brood vs Elixir** — its closest peer, immutable-functional on the BEAM. Brood leads essentially
all of the original 18 rows plus `sieve` and `persistent-map`. Elixir leads the latency rows
(`pingpong` 54 vs 188 ms, `ring` 259 vs 716 ms — ~2.8–3.5×), `ackermann`, `nbody`, and the text
rows where it uses native codecs.

## Memory (peak RSS) and startup

- **Base RSS** (the `startup` row): Brood **20.2 MB — 3rd-lightest**, behind Python (9.6 MB) and a
  megabyte behind Ruby (19.2 MB); ahead of .NET (25.8 MB), Node (42.8 MB), Elixir (71.7 MB) and
  Clojure (103.2 MB). That is still **the lightest of the compiled-class runtimes**. (The
  2026-07-26 run read 19.2 MB and tied Ruby for 2nd; a ~1 MB drift moved the tie, not the
  standing.) Brood stays light across the suite — 3rd on most compute rows, and *1st of seven* on
  `strings` — with the allocation-heavy rows (`sort` 188 MB, `base64` 102 MB, `ring` 98 MB) the
  exceptions.
- **Startup**: Brood ~12 ms — 2nd, ~2 ms behind Python (10 ms); ahead of Node (18 ms), .NET
  (22 ms), Ruby (39 ms), Elixir (180 ms), Clojure (340 ms).

Both are the **warm steady state**. Brood's expanded-prelude boot cache is keyed by build-id, so
the first run of a freshly-built binary costs ~50 ms and ~28.5 MB while it populates, and every run
after is ~12 ms and ~19 MB; the harness's warmup run keeps that populate out of both columns.
(Figures published before 2026-07-26 quoted ~28 MB — the cold boot, which the old aggregation
measured by accident. See [`FRONTIER.md`](FRONTIER.md).)

## How to read it

- **Aggregate single-threaded compute** (the positioning chart's x-axis — Σ wall−startup over the
  original core-compute rows, normalised to the fastest): .NET 1.0× · Node 2.7× · **Brood 3.2×** ·
  Elixir 3.6× · Clojure 7.9× · Ruby 11.9× · Python 28.9×. Brood is **3rd of seven** — behind only
  .NET and Node, ahead of Elixir, at ~3× the fastest (it wobbles ±0.3 run-to-run; the ordering is
  what holds). Every language's figure rose slightly against 2026-07-26 — field-wide drift, except
  for Brood's `fib`, which is the stack-guard cost above. The aggregate deliberately excludes the
  concurrency, error, and wider-range rows —
  they're reported on their own because folding them in would swamp the figure with
  library/representation outliers rather than core language speed.
- **Strongest rows**: 1st at `strings` and `reduce`; 2nd at `startup`, `fib`, `collatz`,
  `wordcount`, `errors`, `errors-deep`, `pfib`; 3rd at `loop`, `ackermann`, `sieve`, `spawn`,
  `http`, `pingpong`, `ring`.
- **Weakest rows — none last**: the 6/7 rows are the by-design text costs
  (`json`/`regex`/`base64`) and representation costs — `pipeline` (lazy-seq churn the JIT doesn't
  cover), `sort` (the cost is *building* the input list), `nbody` (immutable float sim), and
  `bintree` (the one open watch-item).

The per-language source for every benchmark lives under [`bench/`](bench/), seven files per
benchmark named identically except the extension, so the implementations diff side by side. Run
the suite with `python3 bench/harness.py` (see the [README](README.md#running-it) for options).
